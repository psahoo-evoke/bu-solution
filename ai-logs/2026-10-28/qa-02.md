## Prompt (summary)
Add `backend/tests/test_roles.py` (roles × routes per `x-roles`, including 401 for a missing header), upload-limit tests, a reason-codes test, and an LLM-output-validation unit test with a fake client. Redefine the eval headline so that an "Evaluator decides" deferral only counts when its top candidate equals the recorded equivalent, and report three numbers: (a) top-1 candidate agreement, (b) strict decision agreement, (c) wrongly suggested credit. Do not tune on the holdout. Run `pytest -q` until green.

## Inputs used
- `docs/api/openapi.yaml` v0.2.0 (`x-roles`), `docs/adr/0005-role-matrix-default-deny.md`, `docs/security/checklist.md`, `data/synthetic/seed/reason_codes.csv`, `past_decisions.csv` (holdout)

## Output
- **`backend/tests/test_roles.py` (138 tests)**, generated from `x-roles` in the YAML:
  - The guard table must equal the contract, and every served `/api` route must be in the contract.
  - `/health` is public.
  - Missing, empty, unknown and wrong-case roles → 401 on all 13 protected operations (52).
  - The 6 roles × 13 operations matrix (78): 403 when not allowed, neither 401 nor 403 when allowed.
  - Refused decision, batch and reset calls leave no decision and no audit entry. The audit log records the actor role (Department).
  - Batch is allowed for Department. Entra mode fails closed. Security headers are present, including on 401.
- **`backend/tests/test_hardening.py` (12):**
  - 413 by Content-Length, and 413 on a chunked body with no Content-Length; exactly 10 MB is not refused for size.
  - 415 for HTML and ZIP bytes; 422 (no traceback, no paths) for malformed PDFs on both upload routes.
  - Page limit (30 accepted, 31 → 422) using a dependency-free PDF builder; real syllabi still accepted.
  - `student_id` / `ext_id` / query / body pattern validation.
  - `/reason-codes` equals the CSV (22 codes, readable by Student).
  - CORS origins from `TRANSFERIQ_CORS_ORIGINS`, checked with a reloaded app.
  - CSV formula escaping.
- **`backend/tests/test_llm.py` (14)**, using a fake `llm_client`:
  - Valid output is used, with clamping (140 → 100, −3 → 0) and invented outcomes dropped.
  - 7 kinds of invalid output (not JSON, wrong shape, empty, `bu_code` outside the shortlist, non-numeric or boolean overlap, tier outside the enum) and a client exception all fall back to `offline-fallback` with the T17 result unchanged.
  - Even a model that obeys the injection keeps the injection flag, and the injected sentence never reaches the prompt.
  - Prompts for every transcript course contain no `SYN-` ID, no student-name token, no `"grade"` and no `gt_`; the syllabus sits inside `<course_data>`, and the system prompt marks it as untrusted.
  - Both Azure clients prefer the managed-identity bearer token, with the key used only when its env var is set.
  - Importing the app offline loads no `azure*` module.
- **`backend/tests/test_api.py`:** three role tests moved to `test_roles.py` (now 19). Upload and reset tests send an allowed role. **`backend/tests/conftest.py`:** a `client` fixture with a default role (Evaluator) and an `anon` fixture with no header.
- **`docs/quality/eval-report.md`** rewritten with the three numbers, the gate claim and its reasoning, a per-tier table with the deferral count, and a "what changed" section.

- No tuning: the matcher code was not changed in this run; only the scoring definitions were.
